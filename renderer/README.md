# renderer/

A Next.js 15 (App Router) + Tailwind v4 + shadcn/ui renderer that consumes
`reports/m6-design/design-plan.json` and the synthesized design tokens at
`reports/m3-token-synthesis/tokens/dist/`. It is the production target for
M6c: real components, real layout primitives, no hand-written HTML
strings for the re-versioned site.

This scaffold is the **fallback renderer**. The existing static composer
(`skills/web-designer/scripts/compose_site.py`) stays as the proven path
until the next task wires this renderer into `verify.sh` and the 8-gate
validation suite.

## What this scaffold does today

- Reads `reports/m6-design/design-plan.json` at **build time** and renders
  sections in `plan.sections[].order` ascending. Sections in
  `plan.skipped_sections[]` are filtered out (not rendered, still
  audited).
- Bridges the synthesized tokens into Tailwind v4 via a generated
  `@theme inline` block (`app/_tokens.generated.css`). Every color, font,
  spacing step, and radius value used by a Tailwind utility class
  ultimately resolves to `var(--token-*)` declared in
  `reports/m3-token-synthesis/tokens/dist/tokens.css`.
- Exposes a `Section` component with four emphasis-driven layout
  primitives — `hero`, `primary`, `secondary`, `minor` — that produce
  genuinely different column structures at >=1024px (the critique's
  specific defect was the composer stacking content in the left ~45% of a
  1440px viewport).
- Adds only the shadcn components the design plan actually uses:
  `button` and `accordion`. No bulk `shadcn add --all`.
- Uses MIT-licensed motion: `motion` (framer-motion successor) +
  `lenis` smooth scroll. A `check-licenses.mjs` script fails the build
  if a non-MIT motion library (e.g. `gsap`) ever sneaks into
  `package.json`.

## Layout variant grid (>=1024px)

| emphasis   | grid                                | column use                |
|------------|-------------------------------------|---------------------------|
| hero       | `grid-cols-12`, items-start         | left 7 (headline) + 5 (annotation) |
| primary    | `grid-cols-12`, items-start         | left 4 (sticky index) + 8 (body)   |
| secondary  | `grid-cols-12`, items-start         | left 3 (whitespace) + offset-right 9 (content cols 4–11) |
| minor      | `grid-cols-12`, items-baseline      | full 12 (single row band) |

Below 1024px every variant collapses to a single stacked column so the
design is still legible on mobile.

## Commands

All commands run from this directory (`renderer/`):

```sh
# 1. Regenerate app/_tokens.generated.css from upstream tokens.
#    Also runs automatically as `prebuild` before `npm run build`.
npm run sync:tokens

# 2. Verify motion libraries are MIT/Apache/BSD (fails on gsap etc).
#    Also runs automatically as `prebuild` and `npm test`.
npm run check:licenses

# 3. Build the production bundle (runs both above via prebuild).
npm run build

# 4. Serve the built app on http://127.0.0.1:3000
npm run start

# 5. Development server with hot reload.
npm run dev
```

The build always runs `sync:tokens` then `check:licenses` before
`next build`. If either guard fails, the build does not proceed.

## File map

- `app/layout.tsx`            — binds Inter / Poppins / JetBrains Mono
                                via `next/font/google` to the upstream
                                `--typography-font-family-*` variables.
- `app/globals.css`           — Tailwind v4 + shadcn layers; ALL shadcn
                                vars aliased to our `--color-*` tokens.
- `app/_tokens.generated.css` — generated by `npm run sync:tokens`; do
                                not edit by hand.
- `app/page.tsx`              — top-level page; loads the design plan
                                and dispatches each section to the right
                                layout primitive.
- `components/section.tsx`    — emphasis-driven layout primitives
                                (hero/primary/secondary/minor).
- `components/motion-primitives.tsx`
                              — smooth-scroll wrapper + fade-in +
                                signature gold-dot marker.
- `components/ui/button.tsx`,
  `components/ui/accordion.tsx`
                              — the only shadcn components added.
- `lib/design-plan.ts`        — build-time plan loader; honors
                                `skipped_sections[]`.
- `scripts/sync-tokens.mjs`   — token bridge (regenerate on token edits).
- `scripts/check-licenses.mjs`— MIT-only enforcement for motion libs.

## What is NOT in this scaffold

- `verify.sh` is unchanged. Wiring this renderer into the validation
  pipeline and the 8 gates (boot, deps, a11y, perf, audit, responsive,
  motion, source-paired) is the next task.
- `compose_site.py` is untouched. It remains the static fallback.
- No deployment wiring (Vercel/etc.). `npm run start` serves locally.
